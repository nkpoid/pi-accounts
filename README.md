# pi-accounts

Pi の同一セッション内で Codex アカウントを切り替える拡張。
初版は `openai-codex` の OAuth のみ対応し、Pi 0.85.1 で検証している。

## インストール

GitHub リポジトリからインストールする。

```bash
pi install https://github.com/nkpoid/pi-accounts
```

インストール後、Pi を起動するか `/reload` を実行する。

## アカウントの追加とログイン

設定ファイルの編集は不要。
Pi 内で名前を指定して追加する。
provider は Codex に固定される。

```text
/account add work
```

登録後、入力欄が空なら `/login pi-accounts-codex-work` が入るので、Enter で Pi 標準のログインを実行する。
入力中の文章がある場合は上書きせず、実行するコマンドを通知する。
ブラウザで認証する際は、意図した ChatGPT アカウントを選ぶ。
既存の `openai-codex` の認証情報はコピーしない。
追加は即時反映され、`/reload` は不要。
アカウントを追加するだけでは、会話の送信先は切り替わらない。

名前（ID）は設定内で一意の、半角小文字英数字で始まる 1〜64 文字で、2 文字目以降は `_` と `-` も使える。
`work` や `personal` は例であり、任意の名前を使える。

## 新規セッションのデフォルト

`/account` で選んだアカウントとモデルを、新規セッションのデフォルトに保存する。
現在と同じアカウントを指定した場合も保存する。
選択のキャンセルや切り替え失敗では、デフォルトを更新しない。
Pi 標準の `settings.json` の `defaultProvider` と `defaultModel` を使い、次回起動や `/new` で読み込む。

標準の Codex またはこの拡張のアカウントへの OAuth ログインが成功した場合も、そのアカウントをデフォルトに保存する。
ログイン時のモデルは、既存のデフォルト、現在のモデル、ログイン先のカタログの先頭の順に、利用可能なものを選ぶ。
ログインのキャンセルや認証保存の失敗では、デフォルトを更新しない。
**ログインだけでは、実行中のセッションの送信先は変更しない。**
現在の会話を切り替えるときは `/account` を使う。

ほかの実行中セッションへのリアルタイムな追従は行わず、再開したセッションではその会話の選択を復元する。
CLI のモデル指定やプロジェクト設定は、Pi 標準の優先順位でグローバルのデフォルトより優先される。

## 切り替え

現在の会話で使うアカウントを指定する。

```text
/account work
```

- `/account`：ID の一覧から選択する。
- `/account work`：ID を直接指定する。入力補完も使える。
- 現在と同じモデル ID が切り替え先にあれば維持し、なければモデルを選択する。
- **切り替え後のリクエストは、同じ会話の履歴を別アカウントへ送る。** `/account` は実行前に確認する。
- 処理中の応答や継続処理が終わるまで待ち、認証の解決後にモデルを切り替える。
- 認証失敗時は再ログインを案内し、別アカウントや環境変数のキーへ自動で切り替えない。
- 未ログインなら標準の `/login` を案内し、TUI の空の入力欄にそのコマンドを用意する。
- モデル欄の provider（`pi-accounts-codex-work` など）にアカウント ID を含める。独立した `account: ...` のフッター表示は追加しない。

`/account` は TUI、または確認ダイアログに対応した RPC クライアントで使う。
print / JSON モードでは切り替えない。
非対話実行では、ログイン済みの provider を起動時に明示する。

```bash
pi --provider pi-accounts-codex-work --model gpt-5.4
```

モデル選択は標準の `/model` でも行えるが、その場合はこの拡張の引き継ぎ確認を通らない。
モデルの上書き設定には Pi 標準の `models.json` を使い、対象 provider に `pi-accounts-codex-work` などを指定する。
初版のカタログは Pi 同梱の Codex モデルを使い、動的カタログは扱わない。

## 保存先とアカウントの削除

アカウントの登録情報は `getAgentDir()` 配下の `accounts.json` に自動保存する。
通常は `~/.pi/agent/accounts.json`、`PI_CODING_AGENT_DIR` を設定している場合はそのディレクトリになる。
従来の `id` と `provider` を指定した設定もそのまま使える。
設定が不正な場合は読み込みや更新を停止し、上書きしない。

認証情報は Pi の `auth.json` に、`pi-accounts-codex-<id>` ごとに保存される。
ログイン、トークン更新、排他的な保存、ログアウトは Pi が行う。
`/account` で選択した provider/model は Pi のセッション履歴に保存される。
新規セッションのデフォルト保存に失敗した場合も、現在の会話の切り替えは維持して警告する。
保存先の問題を解消してから、同じ `/account 名前` で保存を再試行できる。

削除するときは、先に別のアカウントへ切り替え、標準の `/logout` で対象を選んでログアウトする。
その後、登録を削除する。
確認後に即時反映される。

```text
/account remove work
```

選択中、または認証が残っているアカウントの削除は拒否する。
同じ ID を使う別セッションにもログアウトは影響するが、別 ID の認証情報は変更しない。
名前を変える場合は新しい名前で追加し、ログインし直す。

同時更新はロックで保護し、競合した操作は失敗するため再実行する。
保存中の異常終了で `accounts.json.lock` が残った場合は、すべての Pi を終了してからそのロックディレクトリを削除する。

## 検証

開発には Node.js 22.19 以降を使う。
実行時の Pi パッケージはホストから提供されるため、拡張専用の実行時依存はない。

```bash
npm ci
npm run check
npm test
```

テストは合成 credential と隔離したディレクトリを使い、実アカウントの認証情報を読まない。
Pi の認証保存と更新、native serializer による tool-call replay、模擬 SSE 応答、コマンドのキャンセルと失敗、セッションの復元、依存なしでの CLI 読み込みを検証する。
アカウント間の切り替えでは、別アカウントの署名を Pi の履歴変換で除去し、同じアカウントかつ同じモデルの署名だけを保持する。
Pi 0.85.1 の実バイナリでも、合成認証情報で TUI の直接選択、一覧選択、確認のキャンセル、`/reload`、ログアウト後の再ログイン案内を確認した。
コマンドによる追加、ログインコマンドの入力補助、未ログインの登録の削除は、隔離した設定ディレクトリで TUI の動作と保存結果を確認した。
新規セッションのデフォルト保存は、合成認証情報でログイン成功、キャンセル、保存失敗、新規起動、既存セッションの復元、明示的なモデル指定を検証する。
`/account` からの保存も、新規起動時の選択、同じアカウントの再指定、キャンセル、保存失敗、ほかの実行中セッションを変更しないことを検証する。
起動、切り替え、再読み込み、再開、終了時に独立したフッター表示を追加しないことも検証する。
Pi 0.85.1 の TUI でも、合成認証情報でログインと `/account` による保存を行い、再起動と `/new` 後に保存したアカウントを復元することを確認した。

Pi 0.85.1 にはログイン完了イベントがないため、ログイン後のデフォルト保存はセッション固有の `ModelRuntime.login()` 完了をフックしている。
`ModelRegistry` の内部参照が変わった場合は警告し、ログインと手動切り替えは維持する。

実 OAuth ログイン、外部への推論、実サーバーでの tool-call replay、WebSocket 通信、複数プロセス間の同時 refresh は未検証。
初版にはアカウント管理メニュー、ほかの provider、実行中のアカウントの自動切り替え、認証の import/export を含めない。
設計調査は [`docs/research/pi-account-switcher.md`](docs/research/pi-account-switcher.md) を参照。
